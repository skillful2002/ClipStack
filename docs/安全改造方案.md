> 状态：**全部实施完成（P0 + P1 + P2）**。各模块已于 2026-08-08 ~ 08-09 落地源码并通过编译 / 单测 / 手动验收。
> 最后整理：2026-08-08（方案定稿）；2026-08-09（标注实施状态与验收结论）
>
> 说明：正文主体按设计意图描述，其中 §3.3 / §4.5 / §5 已按 2026-08-09 实际落地实现（内部文件密钥 + 主密码仅应用锁 + Touch ID 走 LAContext）同步修订；§15 补充逐模块验收结论，便于对照审计。

## 1. 背景与目标

ClipStack 是跨平台剪贴板管理器，后台静默捕获剪贴板历史，内容天然包含**密码、API Token、银行卡号、隐私聊天**等高度敏感数据。当前实现重功能、轻安全，存在明文落盘、无应用锁、敏感数据永久累积等问题。

改造目标：在不破坏核心体验（分类、搜索、置顶、收藏、一键复制）的前提下，按优先级堵住以下风险：

- **文件泄露**：数据库文件被他人读取（被盗电脑 / 备份 / iCloud 同步主目录）。
- **无人值守泄密**：解锁的会话里任何人可见全部内容。
- **敏感数据长期累积**：无留存过期，历史无限增长。
- **托盘/录屏泄漏**：菜单栏与屏幕录制直接暴露剪贴板明文。

## 3. 总体设计

### 3.1 全局状态（新增，托管为 Tauri State）
```rust
struct AppState {
    locked: AtomicBool,            // 是否已锁定
    key:    Mutex<Option<Key>>,    // 内部数据库加密密钥（启动时载入 ~/.clipstack/dbkey.dat，常驻内存，与解锁无关）
}
```

### 3.2 三分类映射（保存类型设置用）
- `文本` = { Text, Link, Code }
- `图片` = { Image }
- `文件` = { File }

### 3.3 新增设置项（复用现有 `settings` 表 key/value）

| key | 值 | 默认 | 用途 |
|---|---|---|---|
| `save_types` | JSON `{"text":true,"image":true,"file":true}` | 全开 | 控制捕获哪三类 |
| `retention_days` | 数字串 | `"0"`(永久) | 留存过期 |
| `mask_sensitive` | `"0"`/`"1"` | `"0"` | 敏感内容识别与屏蔽 |
| `auto_lock_idle_sec` | 数字串 | `"0"`(关) | 自动锁定时长 |
| `pw_salt` | 16B hex | 无 | 主密码派生盐 |
| `pw_verifier` | Argon2 哈希 | 无 | 主密码是否已设置 / 校验 |
| `use_touch_id` | `"0"`/`"1"` | macOS `"1"`，其它 `"0"` | 是否启用 Touch ID / 登录密码解锁（macOS，系统 `LocalAuthentication`，不走钥匙串） |

> **密钥存储与解锁策略（已确认 · 决策 3，2026-08-09 按实际实现修订）**：两部分职责完全分离——
> 1) **数据库加密密钥（内部密钥）**：由程序启动时生成并持有，以文件形式持久化于 `~/.clipstack/dbkey.dat`（权限 600，macOS 与非 macOS 共用），并在内存常驻。**与用户主密码完全无关**，主密码的修改 / 清除都不影响落库数据，从而保证「锁定态也持续加密捕获」。
> 2) **主密码仅作应用锁凭据**：只写 / 校验 `pw_salt` / `pw_verifier`（Argon2id），用于解锁与应用锁；**不派生、不持有、不清除**数据库加密密钥。
> 3) **Touch ID / 登录密码解锁**：调用系统 `LocalAuthentication`（`LAContext`）验证当前登录用户（有 Touch ID 时弹 Touch ID，否则回退设备登录密码）；解锁凭据即「当前用户身份」，**不在钥匙串中存储任何可用于解锁的令牌**。旧版曾尝试把密钥写入受 `BiometryCurrentSet` 保护的钥匙串项，因 macOS 26+ 的 API 限制与签名要求而放弃，最终改用 LAContext 方案（见 §15.8）。

## 4. P0 — 数据库加密（应用层，仅加密内容）

> 修订确认：**只加密内容列，其他字段保持明文**；采用应用层 AES-256-GCM，而非整库 SQLCipher。
> 理由：去重用的 `hash`、索引列（`created_at`/`content_type`/`hash`）保持明文，无需解密即可查询；迁移成本最低。

### 4.1 依赖（`Cargo.toml`）
保留 `rusqlite = { version = "0.32", features = ["bundled"] }`，新增：
```
aes-gcm = "0.10"        # AES-256-GCM 内容加密
argon2  = "0.5"         # 主密码 → 密钥派生
zeroize = "1"           # 密钥/明文内存清零
```

### 4.2 新增模块 `src-tauri/src/crypto.rs`
```rust
pub struct Key([u8; 32]);                       // Zeroizing 包裹，drop 清零
pub fn random_salt() -> [u8; 16];
pub fn derive_key(pwd: &str, salt: &[u8;16]) -> Key;          // Argon2id
pub fn hash_password(pwd: &str, salt: &[u8;16]) -> String;    // 存 pw_verifier
pub fn verify_password(pwd: &str, salt: &[u8;16], verifier: &str) -> bool;
pub fn encrypt(key: &Key, pt: &[u8]) -> Vec<u8>;              // 12B nonce || ciphertext
pub fn decrypt(key: &Key, sealed: &[u8]) -> Option<Vec<u8>>;
```
- 密钥派生：`Argon2id`，参数建议 `m=64MB, t=3, p=4`，输出 32B。
- 加密格式：`nonce(12B) || ciphertext`；`content_text` 以 base64 存 TEXT 列，`content_blob` 以原始字节存 BLOB 列。

### 4.3 加密范围（明确）
| 列 | 处理 |
|---|---|
| `content_text` (TEXT) | **加密**：存 `base64(nonce‖密文)` |
| `content_blob` (BLOB) | **加密**：存 `nonce‖密文` 原始字节 |
| `id / content_type / source_app / size_bytes / hash / is_pinned / is_favorite / created_at / deleted_at` | **明文不变** |

- `hash` 在加密**前**用明文内容计算 → `insert_or_bump` 去重无需解密。
- `preview` 不单独存列，读取时由解密后的 `content_text` 现算 → 随内容一同受保护。

### 4.4 `db.rs` 改动
- `insert_or_bump` / `materialize`：写入前对 `content_text`、`content_blob` 加密（密钥由 `AppState.key` 传入）。
- 读路径 `get_history` / `get_item` / `get_trash` / `get_recent_tray` / `get_item_blob`：取出后解密，再回填 `content_text` 与 `preview`（密钥经参数传入；锁屏门禁保证读取时密钥在内存）。
- 新增迁移 `mig_enc_v1`：扫描存量行，对仍为明文的 `content_text`/`content_blob` 加密两列，置标志防重复执行。

### 4.5 密钥存储与解锁（已确认：内部文件密钥 + 主密码仅应用锁 + Touch ID 走 LAContext · 决策 3）

- **内部加密密钥（与用户无关）**：程序启动即由 `keychain::load_or_create_internal_key()` 生成 32B 密钥，以文件 `~/.clipstack/dbkey.dat`（权限 600，macOS 与非 macOS 共用）持久化，并载入 `AppState.key` **常驻内存**，始终负责全部 DB 加解密。仅首次升级时尝试从旧版钥匙串项迁移一次（成功后写文件，后续不再触碰钥匙串）。
- **主密码仅作应用锁凭据**：`setup_master_password` / `change_master_password` / `clear_master_password` 只写 / 校验 `pw_salt` / `pw_verifier`（Argon2id），**不派生、不持有、不清除**数据库加密密钥；`lock()` 只置 `locked` 标记、不清空内部密钥。因此锁定态下复制内容仍照常加密入库（复制永不丢失）。
- **Touch ID / 登录密码解锁**：`unlock_touch_id` 调用系统 `LocalAuthentication`（`LAContext`）验证当前登录用户——有 Touch ID / Face ID 时弹生物识别，否则回退设备登录密码；**不在钥匙串存任何解锁令牌**，解锁凭据即「当前用户身份」。（macOS 26+ 的 LAContext 仅支持异步版，实现上启动 `/usr/bin/swift` 子进程执行验证脚本，规避裸二进制直接调用崩溃；详见 §15.8。）
- **跨平台**：Touch ID 解锁仅 macOS；其它平台解锁统一走主密码路径，`use_touch_id` 默认关闭。

## 5. P0 — 应用锁

- `AppState { locked, key }` 在 `lib.rs` 托管。
- `setup`：数据库加密密钥在启动时即载入（与是否设置主密码无关）；**启动不自动锁定**，主窗口正常显示。仅当用户已设置主密码后，手动锁定 / 窗口失焦 / 闲置超时才会触发锁定并弹解锁层。
- 自动锁：监听 `WindowEvent::Focused(false)` + 闲置定时器（`auto_lock_idle_sec`），触发 `lock()` 并隐藏窗口。

### 新增命令（`commands.rs`）
```rust
setup_master_password(pwd) -> Result<(),String>
unlock(pwd) -> Result<bool,String>          // 校验 pw_verifier，置 locked=false（主密码路径，不动内部密钥）
unlock_touch_id() -> Result<bool,String>    // 系统 LAContext 验证当前用户解锁（macOS）；其它平台回退主密码
lock() -> Result<(),String>                 // 仅置 locked 标记，不清空内部密钥
change_master_password(old,new) -> Result<(),String>
is_locked() -> bool
get_save_types() -> SaveTypes
set_save_types(t: SaveTypes) -> Result<(),String>
```
- 内容类命令（`get_history`/`get_item_blob`/`copy_item`/`copy_image`/`copy_file`）统一加 `ensure_unlocked(state)` 门禁，锁定态返回 `Err("locked")`。
- 前端：`App.tsx` 新增 `LockGate`——`is_locked` 时渲染「设置主密码 / 解锁」层（含 macOS Touch ID 按钮），否则渲染主界面；`SettingsView.tsx` 新增「安全」区（主密码设置/修改、自动锁定分钟数）。

## 6. 新需求 — 保存历史记录类型过滤

- 三分类：`文本` = {Text, Link, Code}；`图片` = {Image}；`文件` = {File}。
- `clipboard.rs::capture()` 在 `materialize`/`classify` 之后插入：
  ```rust
  let cat = match content_type {
      ContentType::Image => "image",
      ContentType::File  => "file",
      _ => "text",   // Text/Link/Code 均归文本
  };
  if !save_types.enabled(cat) { return None; }  // 跳过入库，等同忽略列表
  ```
- 默认值全开；仅影响**新捕获**，不影响已存历史。
- 设置 UI：`SettingsView.tsx` 三个开关（文本 / 图片 / 文件）绑定 `save_types`，改动即调 `set_save_types`。
- **已确认（决策 5）：不提供「一键清理已禁用类型历史」按钮**。保存类型开关仅作用于新捕获；已存历史如需清理，用户可手动删除对应条目。

## 7. P1 — 留存过期（含 trash）

> 修订确认：**清理过期数据时一并考虑 `trash` 表**。

```rust
/// 清理超期数据：history 中未置顶且 created_at 超期；trash 中 deleted_at 超期。
/// days<=0 视为永久保留，直接返回 0。
pub fn purge_expired(conn: &Connection, days: i64) -> rusqlite::Result<usize> {
    if days <= 0 { return Ok(0); }
    let cutoff = now_ms() - days * 86_400_000;
    conn.execute("DELETE FROM history WHERE is_pinned = 0 AND created_at < ?", [cutoff])?;
    // trash 无置顶概念，按「在回收站停留时长」(deleted_at) 过期
    conn.execute("DELETE FROM trash WHERE deleted_at < ?", [cutoff])?;
    Ok(changed)
}
```
- 调用时机：启动 + 监控线程/独立定时器定时（如每 10 分钟）。
- `retention_days` 在 `SettingsView.tsx` 暴露；`enforce_capacity`（5000 条上限）保留作兜底。
- 注：已确认（决策 2）trash 按 `deleted_at` 计时（回收站停留越久越优先清理）。

## 8. P1 — 敏感内容识别

> 已确认（决策 4）：命中敏感规则后**「存储但掩码预览」**，不删除原文（DB 已加密 + 应用锁，存储安全）。

- `clipboard.rs::is_sensitive(text) -> bool`：
  - Token 正则：`(?i)\b(sk-[a-z0-9]{20,}|ghp_[a-z0-9]{36}|AKIA[0-9A-Z]{16}|xox[baprs]-[a-z0-9-]+|eyJ[A-Za-z0-9_-]+\.eyJ[A-Za-z0-9_-]+\.)\b`
  - 卡号：`Luhn` 校验，长度 13–19，去空格/连字符。
  - 密码启发式：长度 ≥ 12、无空格、Shannon 熵 > 4.0。
- `mask_sensitive` 开启且命中 → 写库时新增列 `is_sensitive=1` 且 `preview` 置 `••••••`，原文仍加密存储（DB 已加密 + 应用锁，安全）。
- 新增列迁移：`ALTER TABLE history ADD COLUMN is_sensitive INTEGER NOT NULL DEFAULT 0`（trash 同理可选）。

## 11. 迁移方案

- **加密迁移**：旧明文 `~/ .clipstack/clipstack.db` 在首个加密版本启动时被 `mig_enc_v1` 逐行加密 `content_text`/`content_blob` 两列（其他列不变），无需整体重写库文件。
- **留存迁移**：`purge_expired` 在升级后首次启动即生效，清理 history 与 trash 超期数据。
- 保留 `.bak` 备份直至迁移成功，失败可回退。

### 15.8 Touch ID 解锁方案演进（2026-08-09 · 多轮，最终落地 LAContext）

- **目标**：让 macOS 上可用 Touch ID / 登录密码解锁应用锁，且不引入「钥匙串中存可解锁令牌」的隐患。
- **第一轮（直接解锁不弹 Touch ID）**：最初 `store_key` 用 `security add-generic-password` 且**无任何访问控制**，读取直接返回、不弹 Touch ID（等效秒解）。
- **第二轮（钥匙串 BiometryCurrentSet 尝试，已放弃）**：改用 `security-framework` 绑定 `BiometryCurrentSet` 访问控制。但 macOS 26+ 已移除同步版 `LAContext` API，`SecAccessControl::create_with_flags(kSecAccessControlBiometryCurrentSet)` 因缺少 `protection` 参数返回 `-50 errSecParam`，密钥项**从未写入钥匙串**，读取报 `-25300`；且该路径要求应用签名（dev 裸二进制报 `-34018`），门槛高。
  - **结论**：钥匙串生物识别方案在 macOS 26+ 与 dev 未签名场景下均不可行，**放弃**，改用以下 LAContext 方案。
- **最终方案（LocalAuthentication / LAContext，当前实现）**：
  - `keychain::authenticate_user(reason)` 调用系统 `LocalAuthentication`：有 Touch ID / Face ID 时弹生物识别，否则回退设备登录密码——纯系统级用户身份验证，**不在钥匙串存任何可用于解锁的秘密**，解锁凭据即「当前用户身份」。
  - 因 macOS 26+ 的 LAContext 仅保留异步版 `evaluatePolicy:localizedReason:reply:`，裸二进制经 objc2 直接调用会 `unrecognized selector` 崩溃；故改为启动系统自带的 `/usr/bin/swift` 子进程（Apple 签名、独立进程、崩溃不影响主程序）执行验证脚本，`stdout` 输出 `OK` / `ERR:...`。
  - 解锁流程：前端点「使用 Touch ID 解锁」→ `unlock_touch_id` 命令（在主线程调用 `authenticate_user`）→ 验证通过则置 `locked=false`；与「内存常驻内部密钥」解耦，仅作应用锁解锁手段。
- **验证**：`cargo test` **50 passed / 0 failed**；`tsc --noEmit` 零错误。Touch ID 弹窗需 `tauri dev` 在 Mac 上手动确认。
